# file_operations_demo03

这个 demo 演示“复制文件”的两种实现：整文件读写法和流式读写法。

## 涵盖的操作

- 读取源文件
- 写入目标文件
- 生成副本文件

## 方法对比

| 方法 | 代码位置 | 核心 API | 内存特征 | 行为特点 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| 方法一 | `CopyFile1` | `os.ReadFile` + `os.WriteFile` | 一次性读入内存 | 代码最短、实现最快 | 小文件复制、脚本工具 |
| 方法二 | `CopyFile2` | `os.Open` + `Read` + `os.OpenFile` + `Write` | 分块读取（当前实现最终仍聚合到 `buf_all`） | 便于扩展为真正流式复制 | 大文件复制、需要细粒度控制 |

## 关键区别说明

- 方法一更像“整块搬运”，可读性好，但文件越大内存压力越大。
- 方法二展示了循环读取和 `io.EOF` 判断，这种模式更接近通用 I/O 框架。
- 当前 `CopyFile2` 虽然分块读，但把所有分块都 append 到 `buf_all` 后再一次性写出，仍会占用较多内存。
- 如果想让方法二真正体现“流式优势”，可改成“读一块写一块”，或直接用 `io.Copy(dst, src)`。

## 运行方式

在当前目录执行：

```bash
go run .
```

默认复制路径：

- 源文件：`testdir/test.txt`
- 目标1（方法一）：`testdir/test_copy1.txt`
- 目标2（方法二）：`testdir/test_copy2.txt`

## 代码细节提示

- `CopyFile2` 中目标文件权限传的是 `066`，通常建议改为 `0666` 或 `0644`，更符合常见文件权限设置。
- 实际业务里复制文件，建议优先使用 `io.Copy`，代码更简洁且性能通常更好。
